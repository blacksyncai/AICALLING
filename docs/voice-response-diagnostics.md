# Voice response streaming and diagnostics

Follow-up to the deployed pronunciation-buffer and CSV-precedence fixes. This update keeps models, temperatures, interruption thresholds, endpointing limits, and customer scripts unchanged.

The speech guard now releases completed sentences without waiting for its fixed 24-character tail buffer. A period at the end of a chunk is retained until a following separator is known, to avoid splitting decimals and domains. Question/exclamation endings can pass immediately. Full source text is retained for detecting leaked notes or glued imagined turns arriving in later chunks. Tests exercise every chunk size against known leaks and test the combined guard/pronunciation path with upstream blocked after a completed short sentence.

TurnLatency records session state transitions from user speech ending to the next agent speech start. Continued user speech resets the pending timestamp, overlapping speech does not count as a normal response, and interruption recovery uses a separate bucket. Up to 200 samples are retained per call. Saved metrics add mean, median, p95 and maximum response gaps plus interruption counts/recovery. These are worker/session-state observations, not end-to-end acoustic measurements at a remote phone; carrier/audio transport is excluded. They also do not measure silence between an initial tool acknowledgment and a later tool result.

The old sum of mean EOU/LLM/TTS stages remains as pipeline_sum_estimate. avg_response uses observed gaps when available and otherwise falls back to that estimate. The call detail card labels which measurement is available. No measurements are fabricated for historical calls.

call_config logs now identify semantic-vs-VAD turn detection and enabled speculative generation/audio. Turn-detector initialization failures are logged by exception class. turn_response_gap logs carry timing/model/room and no transcript text. Recent pre-update samples: LOW_RESOURCE_MODE=false; nine opening_line wait samples averaged 1.814s, max 3.05s. That opening wait includes deliberate caller-greeting listening, possible drafted-opening waiting and is not overall response latency.

Further improvements to benchmark on the same model: save an appropriate opening instead of generating it at pickup; warm worker/model connections; inspect STT finalization and semantic end-of-turn confidence; keep a cacheable static instruction prefix with contact context late; shorten contradictory scripts; profile tool requests independently and acknowledge genuine tool waits; compare voice/region routes under equivalent conditions; isolate the voice worker from API/frontend resource contention where resource measurements justify it. Preemptive generation/TTS already exist, and blindly reducing silence/interrupt thresholds can increase interruption errors. Model changes are optional experiments, not a prerequisite for these pipeline fixes.
