# Plivo inventory reconciliation

A server-side worker starts with normal startup jobs when PLIVO_INVENTORY_SYNC_ENABLED is true (default). It polls every five minutes with the configured Plivo project credentials. No API credential or trunk changes are made. It requires a complete, unfiltered account inventory, then individual Number GET 404 responses on two sweeps at least one minute apart before retiring a missing active number. Recent purchases have a two-minute grace. Normally deletion appears after roughly five to ten minutes plus the dashboard’s 30-second refresh; this is polling, not a real-time provider webhook.

Malformed/incomplete pagination, truncation, provider outages, auth/rate-limit errors, and unsuccessful per-number ownership checks never establish deletion. Numbers with voice disabled still count as owned. A number bound to a different project is retained until ownership is positively verified in the configured project; a credential change cannot itself establish release. New purchases/imports record their project binding. This assumes the server credentials point at the project that owns BlackSync’s assigned Plivo inventory.

The worker uses the existing local release path without issuing another carrier DELETE. It clears agent overrides and inbound assignments, removes the number from campaign pools, chooses a remaining default if needed, and pauses running inbound or invalid-pool campaigns with an actionable notice. It preserves the released row and historical calls. A reacquired number resets sync markers. It does not hang up existing calls or automatically resume paused campaigns.

Cleanup is persisted and retried: existing plan phone-quantity reconciliation, ending renewal of a number-only Stripe subscription at period end, and removing the caller ID from the configured Plivo media trunk. No refunds are created. Existing billing-provider support/limitations remain; a cleanup failure leaves pending work, not an active dashboard number.

Additive nullable schema migration: backend/migrations/20261025_plivo_inventory_sync.sql (also applied by normal startup). No backfill marks numbers missing or deletes historical rows. Rollback by reverting the change or disabling PLIVO_INVENTORY_SYNC_ENABLED; already released records are not reactivated automatically. Test in a non-customer project first. Tests use mocked provider responses, not live deletes; production provider connectivity and inventory have not been verified in this environment.
