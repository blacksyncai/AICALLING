# One shared SignalWire outbound route

Investigation confirmed two separate issues:

- The configured SignalWire API credentials receive HTTP 401 Unauthorized on the documented REST inventory and SWML-resource APIs. The earlier Compatibility API request returned HTTP 200 with an empty non-JSON body, obscuring the credential error. New numbers therefore could not be discovered; the fallback only listed caller IDs already on the LiveKit trunk.
- The hosted outbound script created during setup fixes `connect.from` to the first number. Merely adding another trunk caller ID does not change that script.

Use the documented REST `/api/relay/rest/phone_numbers` inventory (data, links.next, id, number, name, capabilities). Follow only HTTPS pagination URLs on the exact configured space and expected collection path. Authentication failures remain visible with the existing trunk fallback; no claims of successful provider discovery are made when credentials fail.

`SIGNALWIRE_OUTBOUND_SCRIPT_ID` identifies the explicitly managed shared SWML resource (this project's resource: 7d5373ef-301d-48a1-bdca-4d06553c2f05). During SignalWire assignment, after verifying ownership through inventory, the integration reads this script and changes only the known one-connect script's `from` to `%{call.sip_data.sip_from_user}`. LiveKit populates SIP From with the caller ID selected for the call; digest authentication username is separate. The destination remains the documented SIP-to-phone extraction expression. The update is read back and is idempotent. Extra/custom script steps are refused rather than overwritten. The SIP address/password/context remain shared across numbers.

After the API credential is corrected, admin can Refresh numbers and Assign a purchased number. Assignment also enables that caller ID on the existing LiveKit trunk. Existing account defaults are preserved; select the new caller ID in Agent Actions or make it the account default through Phone numbers when desired. Caller-ID selection still requires an active number assigned to the same workspace. No automatic number purchase, deletion, replacement, number rotation or test call is performed. Buying a number does not establish its spam reputation, and this update does not resolve carrier spam classification.

Validation: 24 focused inventory, assignment, routing, recording and phone regression tests passed. This includes REST pagination, foreign-host rejection, preservation of destination, non-mutating/idempotent script conversion, custom-script refusal and read-back verification. The JavaScript expressions were checked with two caller IDs and an independent destination. The replacement API token was verified live: both purchased numbers were returned and the existing SWML resource was read successfully. The shared script was updated and read back with the dynamic caller-ID expression; the verified token and script resource ID were saved to Railway. These checks do not establish a successful live multi-number call.

Live inventory uses a capabilities array (for example voice and fax), although the current documentation also describes an object. The parser accepts both shapes; actual application-service calls returned both real numbers and verified the shared dynamic script using the saved server credential. The initial build was canceled before rollout to include this verified-response correction.
