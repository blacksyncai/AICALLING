# Notification history and Radar MCP

Admin → Accounts → select account → Notification history now combines each client alert queue/send state, linked provider delivery events, and the separate shared internal copy. Provider receipt keys join exactly to alert IDs or call IDs; recipient/subject similarity is never used to infer a match. Historical rows without linkage remain unknown. Client success is committed before the optional copy. Copy failures/disabled configuration are recorded independently and do not resend the client email. No new automatic copy retries are introduced. Provider acceptance is distinct from delivered/opened status; delivery still requires webhook events. A response without a provider receipt is unconfirmed.

Schema additions are nullable for old rows. Startup adds the columns/index idempotently; explicit PostgreSQL migration: backend/migrations/20261025_notification_history.sql. The sender records the actual sender and idempotency key alongside its receipt and enriches webhook-first records without overwriting their delivery state. No email bodies or credentials are exposed in history.

Radar MCP supports existing campaign_id via radar_launch (same dashboard validation and assignment protection). An explicit empty external_ids list is never interpreted as all contacts. New tools: radar_list_automations, radar_automation_resources, radar_preview_automation, radar_save_automation, radar_set_automation_state, radar_automation_activity, radar_run_automation. Structured rule schemas come from the installed Pydantic models. Save/edit produces drafts; edit resets active rules to draft as in the UI. State changes and selected historical runs require confirmed=true. Tools inherit manager role, entitlement, tenant, CRM source/destination, and active-rule checks. Manual runs queue only the explicitly selected past calls; they do not place phone calls. No arbitrary CRM API/code execution is exposed.

Validation uses disposable databases and mocked external HTTP; no real emails or CRM writes performed. Desktop/mobile history preview checks use sample data. Refresh the ChatGPT/Claude connector after release to discover new tools.

Rollback: revert the application commit together; nullable additive columns can remain. Apply to a limited admin account first, send one authorized test notification, check its two receipts and webhook events, and test MCP draft → preview → activation approval. Runtime deployment and live provider verification are separate from local validation.
