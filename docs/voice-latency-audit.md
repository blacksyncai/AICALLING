# Voice latency and quality audit

Production call_config logs sampled on 2026-10-16 show gpt-4.1-nano, no saved first message, min endpoint delay 0.35s/max 2.5s, interruption minimum 0.5s/two words. LOW_RESOURCE_MODE is explicitly false, so the resource-saving flag is not disabling semantic turn detection. Successful turn detector initialization still needs call-level verification; the worker catches initialization failures.

A verified local buffering defect: pronounce() retained the maximum configured phrase length for every stream, waiting for additional model text even when a reply contained no matching pronunciation. The replacement holds only a trailing potential phrase at a word boundary, remembers preceding context across emitted chunks, and preserves case-insensitive replacements. Tests block upstream after a short ordinary response and verify it is yielded without waiting for the next chunk; pronunciation behavior is checked across all chunk sizes, including Unicode case matching. This is an intermediate text-stream improvement, not a measured reduction in live caller-to-audio time.

Other current factors: the speech guard retains 24 characters to detect internal-message leaks; the repeat guard can reject a repeated opening and make a second model request; false-interruption recovery is three seconds; agent openings may invoke a model when no fixed opening is provided. Existing configurable-agent sessions already enable preemptive generation and preemptive TTS. Do not simply enable features already on or blindly lower all interruption thresholds.

Current avg_response is the sum of separate mean EOU/LLM/TTS metrics. With preemptive/overlapping work it is not a direct measurement of the caller's perceived gap, and averages hide slow tail turns. Further tuning should correlate actual last-caller-speech/first-agent-audio timings, interruption events and tool durations per call, reporting distributions by model and carrier.

Recommended quality experiment: compare one existing nano agent with GPT-4.1 mini (or another configured candidate) on the same representative cases; measure time and correctness rather than switch every account. Use a fixed contextual opening, concise task instructions, explicit call state and source data, and verified tool receipts. Include interrupted answers, voicemail, wrong numbers, callback requests, previously supplied information and booking-tool failures in regression conversations. The separate redial CSV precedence fix protects source context and is included as this branch's parent.

No live agent settings, model choices, calling thresholds or carrier configuration were changed during this audit. No calls were placed. Both the redial CSV fix and this buffering fix remain undeployed until explicitly released. Existing previously overwritten CSV values are not repaired automatically.
